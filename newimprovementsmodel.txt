### 2. Parameter-Efficient Fine-Tuning (Practical for Consumer Hardware)
Instead of full fine-tuning (memory-intensive), use LoRA:

```python
from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=8,                    # Start with low rank
    lora_alpha=32,
    target_modules=["q", "v"],  # T5 attention modules
    lora_dropout=0.1,
    bias="none",
    task_type="SEQ_2_SEQ_LM"
)

model = get_peft_model(base_model, lora_config)
# Saves ~70% memory vs full fine-tuning
```

### 4. Accessibility-Specific Loss Function
Modify training to prioritize accessibility features:

```python
def accessibility_loss(logits, labels, input_text):
    base_loss = cross_entropy(logits, labels)

    # Accessibility bonuses (on decoded text)
    decoded = tokenizer.batch_decode(logits.argmax(-1), skip_special_tokens=True)

    bonus = 0.0
    for text in decoded:
        # Shorter sentences = better for ADHD/dyslexia
        avg_sent_len = len(text.split()) / max(text.count('.') + text.count('!') + text.count('?'), 1)
        if avg_sent_len < 15:  # Target: <15 words/sentence
            bonus += 0.1

        # Word frequency bonus (SUBTLEX frequencies)
        words = text.lower().split()
        freq_score = sum(word_freq.get(w, 0) for w in words) / len(words)
        if freq_score > threshold:
            bonus += 0.05

        # Concrete word bonus (lower AoA = easier processing)
        concreteness = sum(concreteness_scores.get(w, 0) for w in words) / len(words)
        if concreteness > threshold:
            bonus += 0.05

    return base_loss - (bonus * accessibility_weight)  # Minimize loss
```

### 5. Evaluation Metrics Beyond ROUGE
Track these accessibility-relevant metrics during validation:

| Metric | Why It Matters | Target Range |
|--------|----------------|--------------|
| **SARI** | Standard simplification metric | > 40 (good) |
| **FKGL** (Flesch-Kincaid Grade) | Reading level | 3.0-6.0 (ideal) |
| **ASL** (Avg Sentence Length) | Critical for ADHD/dyslexia | < 15 words |
| **% Concrete Words** | Easier processing | > 40% |
| **Dependency Depth** | Syntactic complexity | < 4.0 |
| **Lexical Diversity** (Type-Token Ratio) | Vocabulary simplicity | > 0.4 |

### 6. Integration with Your Mode System

### 8. Critical Safety Checks for Accessibility
Before deploying any fine-tuned model:
- **Adversarial tests**: Try sentences with idioms, metaphors, complex syntax
- **Mode compatibility**: Ensure output works with dyslexia/ADHD/autism post-processors
- **Cognitive load measurement**: Use LEX tool or compute features manually
- **User testing**: Even 5 neurodivergent users can catch critical issues
